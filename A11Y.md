# Accessibility invariants

The Definition of Done points here. Each item is enforceable, and each carries
its source so it can be argued with.

## Enforced in code today

- Text on a color uses `readableForeground()`. It selects by comparing
  contrast ratios, never by thresholding luminance. The `#000`/`#fff` pair
  clears 4.5:1 on every possible color, worst case 4.58:1 at luminance 0.179,
  verified by a sweep of 3,168 combinations across the picker range.
- `contrastOver(fg, bg, alpha)` exists so translucent text can be measured.
  It is how the prototype's `opacity: .8` caption was found to fail, and that
  opacity is not reproduced in the implementation.
- `needsBorder(hex)` decides the hairline on light swatches. This is a
  contrast affordance: without it White, Cream and Light grey vanish into the
  `#d8d5cf` background.
- Color names use OKLab distance rather than RGB. This is the right default
  for perceptual distance on arbitrary camera-read colors, and the name is
  the only non-color channel available to a color-vision-deficient user, so
  naming accuracy matters. It is not a fix for a demonstrated RGB failure: for
  this 18-color palette, the two metrics agree almost everywhere, the
  supposedly confusable warm neutrals sit 37 to 40 RGB units apart, and two
  searches for a case where OKLab beats RGB turned up only near-ties.
  The naming contract only holds near the palette, so `colorName` stops at
  its edge: past `NAME_MAX_DISTANCE` no palette name is claimed, and the
  color is described from its own lightness, chroma and hue instead, as
  "bright green" instead of a confident "Cream". A description deliberately
  carries less than a palette name: a user confirming a camera read can act
  on it, where a wrong name reads as information. Neutrals are exempt,
  because between two neutrals there is no hue to get wrong.
- `jsx-a11y/no-static-element-interactions` and
  `jsx-a11y/interactive-supports-focus` are errors. These are the two rules
  that catch the prototype's unlabeled `<div>` with pointer handlers.
- The one route the app has today is scanned with axe at WCAG 2.1 AA. Both
  E2E checks call `page.goto('/')` directly, so this holds per route, not
  app-wide; each needs extending to cover new routes as M3 adds them.
- That same route is checked for horizontal overflow at 320px, with the same
  per-route caveat.

## Owed by later milestones

- `blockLabel(slot, hex)` in `src/color/palette.ts` builds the accessible
  name for a color block, e.g. "Top: Pale blue", but nothing calls it yet:
  `src/App.tsx` still sets a hardcoded `aria-label`. Wiring it in is screen
  work for M3.
- The peek strip is a `<button>` labeled "Next suggestion" (M3).
- The long press has a non-gesture alternative — "Keep this" in the
  alternatives sheet. It does not exist in the prototype (M3).
- Season sort and toasts announce through a live region. Radix Toast covers
  the toast; the re-sorted palette grid is application code (M3).
- Hit targets use the `touchTarget` token everywhere, never a repeated
  literal (M3).
- The swipe position indicator needs a text equivalent. The prototype conveys
  position through dot opacity alone (M3).
- All motion and every `navigator.vibrate` call gates on
  `prefers-reduced-motion`. Motion durations are already tokens, so a single
  media query can zero them (M3).
- Focus moves and is announced on every screen transition. The prototype swaps
  branches inside one component, so focus lands nowhere (M3).
- The swipe must ignore gestures where vertical movement dominates, per the
  handoff notes. The prototype never reads `clientY` (M3).
